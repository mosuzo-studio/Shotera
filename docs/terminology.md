# Shotera 术语与卖点口径

站点（首页、关于、版本、FAQ、changelog、README、15 语言页面）与 App 界面必须说同一套词。本文件是**站点侧的唯一术语来源**：新词先在这里登记，再写进任何页面。

- 事实依据（唯一权威）：App 语言包 `D:\project\research\ShotxAI\src\i18n\{zh-CN,en,zh-TW,ja,pt-BR,es,de,fr,it,ko,ru,ar,nl,pl,sv}.js`
- 对外事实红线：App 仓库 `docs/推广文案/00-事实基线.md`（本节只摘录站点会踩到的部分，冲突时以它为准）
- **规则：一个功能只有一个名词，动词可以自由。**「不再使用」列里的词不得再出现在任何对外文案里。

## 1. 卖点分层（页面结构也照这个来）

| 层  | 内容                                                                                                 | 出现在                              |
| --- | ---------------------------------------------------------------------------------------------------- | ----------------------------------- |
| L1  | 截图（含两种完成模式）、长截图、贴图、录屏 & GIF、AI 能力（AI 抠图 / AI 擦图 / 离线 OCR / 图片翻译） | 首屏胶囊 + 首屏下方的模式卡         |
| L2  | 标注 10 件套、二维码识别、自定义截图、图片编辑、演示模式                                             | 功能区（左右交替图文段 / 图标清单） |
| L3  | 快捷键自定义、历史记录、多显示器与 HiDPI、深色模式、轻量、15 语言、应用内自动更新                    | 细节列表 / FAQ                      |

首屏胶囊取 L1 五项；判断规则：**能各自用「一张图 + 一句话」讲清、且不是别的功能的一小步** 才进胶囊。

关于页的版式例外：「核心能力」（L1 区）把 离线 OCR 单列一张卡，AI 一张收窄为「AI 抠图与擦图 / AI cutout & eraser」；「更多能力」（L2 区）在 L2 之外再给 图片翻译 一张独立卡片，并把 多显示器、深色模式（L3）也收进同一区。其余页面仍按本表分层。

## 2. 核心功能（L1）

| 站点名词   | English                      | 允许的动作词                   | 不再使用                               | App 键名（zh / en）                                                                    |
| ---------- | ---------------------------- | ------------------------------ | -------------------------------------- | -------------------------------------------------------------------------------------- |
| 截图       | Screenshot                   | 框选、截取、吸附、检测窗口     | 截屏、抓图（正文口语可，但不作功能名） | `modebar.shot` = 截图 / Screenshot                                                     |
| 长截图     | Scrolling capture            | 滚动、自动滚动、拼接           | **滚动截图**（旧写法）                 | `modebar.long` = 长截图 / Scrolling Capture                                            |
| 贴图       | Pin to Desktop（短标签 Pin） | 钉、钉在桌面、悬浮、缩放、翻转 | **钉图**（旧写法）                     | `toolbar.pin` = 钉在桌面 / Pin to Desktop                                              |
| 录屏       | Screen recording             | 录制、导出、无时长限制         | 视频录制                               | `modebar.rec` = 录屏 / Record                                                          |
| GIF 录制   | GIF recording                | 录制、导出、帧率               | GIF 动图、动图录制                     | `modebar.gif` = GIF 录制 / GIF Recording                                               |
| AI 抠图    | AI cutout                    | 抠出、去背景、透明底           | 智能抠图、一键去背                     | `toolbar.cutout` = AI 抠图 / AI Cutout                                                 |
| AI 擦图    | AI eraser                    | 擦除、补全、去水印             | **AI 修图**、智能擦除                  | `toolbar.aiErase` = AI 擦图 / AI Erase                                                 |
| 离线 OCR   | Offline OCR                  | 提取文字、识别                 | OCR 文字识别（旧的叠词写法）           | `toolbar.extract` = 提取文字 / Extract Text；`ocr.title` = 文字识别 / Text Recognition |
| 图片翻译   | Image translation            | 翻译                           | 翻译截图                               | `toolbar.translate` = 翻译 / Translate                                                 |
| 二维码识别 | QR & barcode scanning        | 识别、扫码                     | 二维码扫描                             | `modebar.qrcode` = 二维码识别 / QR Code                                                |

英文口径：站点名词沿用 App 的英文标签（Title Case，如 Pin to Desktop / AI Cutout / Scrolling Capture）；正文里可用句首大写与短形式（pin、AI cutout、AI eraser）；changelog 保留 App 自己的英文说法（long screenshot、pin window）。中文侧同理：名词唯一（贴图 / 长截图 / AI 擦图 / 离线 OCR），动词自由。

**录屏与 GIF 的呈现规则**：App 里这是模式栏的两个独立模式（`modebar.rec` = 录屏、`modebar.gif` = GIF 录制），两个名字都保留；但**站点的标题位（首屏胶囊、模式卡标题、页脚链接）只写「录屏」**，GIF 放到正文里讲（如「一键导出 MP4 或 GIF」）。**例外（2026-09-28 起，仅两处）**：关于页 L1「核心能力」的卡片、首页「日常三件事」区块的录屏卡，标题写作「录屏 & GIF / Recording & GIF」。

「离线 OCR」的措辞边界：可以说 OCR、AI 抠图、AI 擦图**本地处理、不上传**；**不得**泛化成「截图和录屏数据都不会离开电脑」——图片翻译会把图像发给第三方服务（详见 §5）。

## 3. 两种完成模式（截图收尾方式）

| 站点名词   | English       | 含义                                           | App 键名                               |
| ---------- | ------------- | ---------------------------------------------- | -------------------------------------- |
| 优雅简洁   | Elegant       | 框选完成即复制到剪贴板并弹通知，点通知进编辑器 | `settings.capture.captureDoneNotify`   |
| 所见即所得 | Live annotate | 框选完成立即显示标注工具栏，不切窗口完成编辑   | `settings.capture.captureDoneAnnotate` |

统称「两种完成模式」（App 首次使用弹窗标题即「截图支持两种完成模式」）。**不要**再造「简洁模式 / 工具栏模式」这类第三套名字。

## 5. 对外表述红线（违反即回退）

摘自事实基线 §3/§4，站点文案同样适用：

- **不写价格**：售价、免费范围、买断或订阅方案（客户端尚未形成一致的授权实现）。
- **不写**：源代码许可证、下载量 / 用户量 / 转化率 / 收入、GitHub stars 之类的旧社会证明。
- **不做不可证明的定位**：「唯一」「最强」「行业领先」「Windows 版某某」等。
- **不做竞品横评**：与 Snipaste / ShareX / Snagit 等的功能或价格对比，除非发布前逐项实测并留证据。
- **不承诺平台**：macOS、Linux、ARM64 支持。
- **不用无测试条件的数字**：「一秒完成」「效率提升三倍」这类；引用项目内基准必须写明限定语（例：68.2% 提速须写作「项目内 Windows 双屏基准」）。
- **隐私表述不得绝对化**：禁用「实际图像或视频数据不会离开电脑」「全部本机完成」「不用联网」这类写法；涉及图片翻译等功能时必须说明数据去向。
- **不统称开源/可商用**：软件许可、模型许可（如默认抠图模型的非商用条款）需分别说明。
- 安装包体积、系统最低版本、代码签名等**未与当前对外资料统一确认前**不写进正文；站点若要写，先在此登记并确认依据。

## 6. 维护方式

1. 改术语：先查 App 语言包 → 更新本表 → 再改页面文案（15 语言同步时取同一键名，不自行翻译）。
2. 新增卖点：先判断进 L1/L2/L3 哪一层，再决定它出现在首屏、功能区还是细节列表。
3. 站点与 App 用词不一致时，以 App 语言包为准；App 也没有的词，先在本表登记再使用。
